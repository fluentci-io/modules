# Betterleaks

PureScript module for `betterleaks`, compiled to WebAssembly.

## Requirements

Install `betterleaks` on the FluentCI host and make it available on PATH,
or supply an executable path with `executable`. The module checks the host OS,
working directory, and executable before running. Linux, macOS, FreeBSD,
OpenBSD, and NetBSD hosts are accepted where the upstream CLI is available.
This module uses an existing installation; it does not install the tool.

Install Betterleaks 1.10.x; the named commands target its stable v1 CLI, not the incompatible v2 development CLI. Homebrew's versioned cask uses betterleaks-v1, which can be selected with executable. Named scans force redaction, a nonzero findings exit code, and validation=false, so detected credentials are not checked against provider APIs. Automatic loading of target-local configs is disabled; provide an explicit config when needed. Use run.arguments for other native operations, and protect run reports.

## Usage

Call `fluentci run betterleaks scan_dir` with this JSON object as plugin input:

```json
{
  "project": ".",
  "runDir": ".fluentci/runs/betterleaks-001"
}
```

Exports: `run`, `version`, `scan_dir`, `scan_git`.
See [OPTIONS.md](./OPTIONS.md) for each command's typed fields and
[schema.json](./schema.json) for machine-readable input definitions.
`run` accepts an `arguments` array for other native CLI operations:

```json
{"runDir": ".fluentci/runs/betterleaks-002", "arguments": ["--help"]}
```

`project` is the local working directory (default `.`); use a fresh `runDir`
for each invocation. `timeoutMs` defaults to 900000. Arguments are passed
literally without shell expansion. A nonzero exit status fails the invocation.
Commands execute immediately; use the CLI's preview or dry-run options when needed.

Authentication uses the native CLI configuration and inherited host environment.
Keep credentials out of JSON input: execution plans and CLI logs are persisted.
The output is the JSON execution report from `runDir/result.json`; task stdout
and stderr are stored in that run directory. See the [shared execution guide](../../lib/cli/README.md).

## Development

```sh
npm ci
npm run build
npm test
```

Builds produce `dist/plugin.wasm`. The shared CLI engine is in
[lib/cli](../../lib/cli); entry points, schemas, and argument references are
generated by `python3 ../../scripts/generate_cli_modules.py` from its catalog.
Tests exercise compiled command validation and optional native scans of
temporary fixtures. Install the pinned test binary with
`python3 ../../scripts/install_security_test_tools.py --directory /tmp/security-tools --tool betterleaks`,
add that directory to PATH, and set `FLUENTCI_REQUIRE_SECURITY_TESTS=1` to require
the native check. Fixtures contain synthetic markers or package metadata; tests
do not scan this repository or verify real credentials.
